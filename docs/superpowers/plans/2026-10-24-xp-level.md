# XP, Level, Truhen und Profil Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a server-booked XP and level system with chests, level-bound titles and frames, a school-day streak with a weekly shield, an avatar badge that opens a new profile area, and game-like feedback (flying XP, level-up celebration, chest opening), so every solved quest gives visible progress.

**Architecture:** XP is booked like coins: `xp_ledger` + `profiles.xp/level`, written only by an internal `grant_xp` that existing RPCs call inside their transaction (quests, stamps, tutorial, first placement). Level-ups create rows in `chests`; opening a chest rolls coins on the server. The browser reads everything through one RPC `my_progress()` and the `progress` field that the extended RPCs return, behind an injectable `ProgressApi` so all UI is testable without Supabase.

**Tech Stack:** Postgres migration + PGlite SQL tests (pattern of `web/tests/sql/tutorial-house.test.ts`), TypeScript strict, Vite 5, three.js 0.170.0, Vitest 2 + happy-dom, Playwright, ffmpeg (one-time asset conversion).

**Spec:** `docs/superpowers/specs/2026-10-24-xp-level-design.md` (all numbers below come from it). Related: `docs/superpowers/specs/2026-10-21-build-feedback-design.md` §6 (sounds), `docs/superpowers/specs/2026-10-21-tablet-ui-navigation-design.md` §10 (areas, dialogs).

## Review Focus

1. **Answering the same quest twice / on two devices at once** → XP, day goal and streak booked once; second response has `gained: []`. (SQL test in Task 2.)
2. **Streak across weekend, holiday week and a missed school day** (Fri → Mon keeps it; holiday week keeps it; one missed Tuesday uses the shield; a second missed day the same week restarts at 1; a new Monday refills the shield) → exactly the spec rules. (SQL tests in Task 2 with a controllable `quest_today()`.)
3. **Several level-ups in one booking** (stamp + backfill, or 400 XP at once) → one chest per level, correct `big` flags, one celebration listing all of them. (SQL test in Task 1, UI test in Task 8.)
4. **Opening a chest twice, or tampering** (another pupil's chest id, opening via direct table write, `set_title` above own level) → second open returns the same result without a new coin booking; foreign/locked → error; tables not writable. (SQL tests in Task 4.)
5. **Slow network or error during chest opening / level-up** → chest keeps wobbling until the answer, error text with retry, coins never shown before the server confirmed; leaving the dialog keeps the result for the profile. (UI tests in Task 8.)
